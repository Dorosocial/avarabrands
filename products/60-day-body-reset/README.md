# 60-Day Body Reset — page system

`index.html` is a self-contained preview of all nine page templates for the
**60-Day Body Reset** downloadable PDF program: Cover, How This Program Works,
60-Day Calendar Overview, Weekly Overview, Daily Workout, Exercise Library
Card, Mini-Program Divider (all 7: Face + Neck, Core + Waist, Glutes + Hips,
Arms, Back + Posture, Inner Thighs, Mobility), Progress Tracker, and FAQ &
Safety. Open the file directly in a browser — no build step, no external
requests.

## Where this came from

The tokens, type scale, spacing, component set (`Badge`, `Tag`, `Callout`,
`Divider`, `StepNumber`, `StatPill`, `MuscleTag`, `ProgressRing`) and all nine
page layouts were authored as a React/JSX brand kit for this product. This
file ports that system 1:1 into static HTML/CSS — same colors, same type
(Bricolage Grotesque + Public Sans, self-hosted as inline `@font-face`
so the page needs zero network access), same 840×1088 page grid, same
copy — so it can be viewed anywhere without a dev server.

The one gap in that kit was the avatar: every avatar spot was an unfilled
placeholder, because no illustration existed yet. This file fills that gap
with a single illustrated instructor built from ten reusable SVG poses
(`<symbol>` defs near the top of the file, instantiated via `<use>`)
covering every avatar placement in the product: standing hero, seated
face/neck, standing core press, hip hinge, bicep curl, wall angels,
Copenhagen plank, side-lying leg circles, mobility reach, and rest. Same
face, hair, skin tone and "uniform" (terracotta crop top, charcoal leggings)
in every pose, so she reads as one character throughout — no other art or
copy was changed.

## Editing

- Colors/type/spacing tokens live in the `:root` block at the top of the
  `<style>` — change once, every page updates.
- Add a new pose by adding a `<symbol id="pose-…">` to the shared `<svg
  style="display:none">` defs block, then reference it anywhere with
  `<svg viewBox="0 0 200 240"><use href="#pose-…"/></svg>`.
- The calendar grid, progress-tracker dot grid, and the seven mini-program
  dividers are generated by the `<script>` at the bottom from small JS
  arrays (`CATS`, `DIVIDERS`) — edit the data, not the markup.
- Each "paper" page is fixed at its real print size (840×1088) and scaled
  to fit the viewport via `.page-frame` + a resize listener — the print
  colors don't adapt to dark mode (this is a designed print artifact, not
  UI chrome), but the surrounding shell/nav does.
